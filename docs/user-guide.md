# USB 轨迹工具使用说明

适用环境：Mate 80 Pro／SGT-AL50，HarmonyOS 7.0.0.109（SP6C00E105R3P3，API 26），HDC 3.2.0d，testhelper 1.0.1，M0 独立定位读取 1.0.0。运动世界测试对象为 7.3.92；兼容性以[验收报告](verification/sport-world-compatibility.md)为准。

当前定位执行主体在电脑，运行期间保持 USB 连接。`verifiedStandalone=false`；拔线、锁屏或退出电脑进程不保证手机自动恢复。

## 启动

需要 Node 26.1.0 或更高版本，在仓库根目录运行：

```powershell
npm ci
npm run build
npm test
npm start
```

打开终端输出的 `http://127.0.0.1:<随机端口>`。服务只监听本机；关闭网页不会停止服务。不要将端口转发给外部网络。

本机需要已验证 HDC 工具 `tools/hdc/hdc.exe`、能力报告 `docs/verification/m0-report.json` 及报告引用的证据。它们包含本机信息或不属于可分发源码，未提交到 Git；换电脑或换设备须重新准备、验证。可用启动进程的 `HDC_PATH`、`M0_REPORT_PATH` 环境变量指定其他路径，相对证据路径依赖仓库工作目录。缺少有效证明时页面可打开，但不能开启模拟。

1. 手机解锁并连接 USB，打开「M0 独立定位读取」，授权精确定位并点击“开始读取”，保持前台亮屏。验收长会话时可由本人临时延长自动锁屏时间，结束后恢复个人设置。
2. 在页面明确选择已验证设备；掉线后不会自动选择其他手机。
3. 编辑或导入 WGS-84 路线，检查预览、配速、圈数和方向，点击“应用配置”，再点击开始。
4. 开始会先关闭残留模拟，在 35 秒内取得 5 个新的稳定正常样本后才启用。样本距中位点须均不超过 10 米、精度不超过 50 米。手机静止也可能有定位漂移；基线不足时等待正常定位稳定，再重新开始。

本机能力报告的保守有效期为 **2027-10-17 09:08:52 UTC（北京时间 17:08:52）**，来源是读取应用 Profile 的已知到期时间；**系统 testhelper 授权期限未单独证实**。系统、工具、目标设备、签名或证明变化时须重新核实；报告到期后控制器禁止新启用／发送，已有会话仍应尝试停止。

## 路线与运行

路线 JSON 包含 `schemaVersion: 1`、非空 `name`、`coordinateSystem: "WGS-84"` 和至少 3 个不同的 `points`，每点含数值 `latitude`、`longitude`。也可在界面每行填写“纬度, 经度”。末点自动连回首点，可在文件末尾重复首点一次；相邻重复点、零长度段及含闭合段在内超过 500 米的连接会被拒绝。

底图来源若使用其他坐标系，应先在导入边界正确转换并保存来源说明。仓库[合成样例](../desktop/tests/fixtures/track.json)仅供测试格式，不是真实操场路线。本次验收的闭合控制路线同样没有实测操场依据。

配速单位为秒／公里，例如 300 表示每公里 5 分钟；正整数圈数和方向共同决定目标距离、时长。输出按单调时间推进，调度延迟后使用当前进度。界面 1 秒采样设置不保证实际每秒送达；当前单点 GPX 传输、摘要核对和工具调用有耗时。GPX 写入坐标和时间，未证明能设置原生速度或朝向。

暂停保持最后位置、运行时间和距离，继续不会补跑暂停时间；暂停期间模拟仍开启。手动停止会立即进入清理。全部圈数结束后，控制器停止推进，等待一个新的独立终点回调（距终点不超过 5 米，最多 15 秒）再关闭；等待期间不能暂停／继续，可以手动停止。超时仍尝试关闭并在私有日志保留 `TERMINAL_OBSERVATION_TIMEOUT`，定位恢复成功不代表这次终点验收成功。

页面分别显示预期、已提交和独立读取位置。提交被接受不代表读取应用或运动世界已经收到。修改输入、其他标签页替换配置、连接中断或结束一次会话后，重新应用配置才可开始。

## 停止与恢复

点击停止后继续保持 USB、独立读取前台和调度运行。关闭被接受后仍显示“恢复待确认”；只有清理之后 45 秒内取得至少 3 个不同的新回调，同时满足以下条件，才显示“恢复已确认”：

- 精度不超过 50 米，位置距本会话启动前的原基线不超过 50 米。
- 距所有尝试注入的位置至少 100 米。
- 时间新鲜，定位与接收时间差不超过 5 秒，未明确标记为模拟。

`source`／`isMock` 不可读时保留 `null`；不能单凭标记未知判断正常。路线距离真实基线太近时，恢复判据可能无法区分两者，结果保持未确认。

断线时停止继续发送，手机位置状态未知。重新连接同一手机，解锁并恢复独立读取，**先点击停止重试**；旧关闭回执不能替代重连后的清理。超时后同样重试停止，始终沿用原基线。恢复未确认前不能重新配置或开始；不要用另采基线覆盖失败。

请先点击停止并等待“恢复已确认”，再退出服务。Ctrl+C 会关闭服务、尝试停止并等待独立恢复，退出等待上限 60 秒；本轮较长会话实际在截止时仍为 stopping，未完成自动恢复，需人工补救，不能把 Ctrl+C 当作可靠的一步恢复入口。失败会明确报告未确认。强制终止、断电后原会话基线不会自动在新进程中重建；保留原日志，按下面的人工关闭入口处理，并核对原会话证据。

在 PowerShell 中先列出设备，再用**已核实的原 USB 目标**关闭：

```powershell
& .\tools\hdc\hdc.exe -s '127.0.0.1:8710' list targets -v
# 将占位符替换为本机证据中的原目标，确认是 USB Connected。
& .\tools\hdc\hdc.exe -s '127.0.0.1:8710' -t '<原USB目标>' shell testhelper disable-location-mock
```

同时检查退出码和 `Disable location mock successfully.` 文本，随后在独立读取页取得新正常位置。取消读取订阅、退出页面或删除 GPX 不会关闭模拟。原会话恢复无法核实时保留未确认；不要只凭关闭成功或重启宣称恢复。

执行器仅按路径和 SHA-256 删除自己创建的文件，再删除空专属目录。摘要不符时保留文件并报告失败；不要递归清理设备公共临时目录。强制退出导致的遗留文件应依据原私有清单逐项核实处理。

追加版本已将摘要核对和删除按最多 16 个自有路径分批执行，减少长会话清理耗时；真实手机 80 文件测试约 3.3 秒。完整进程退出与原基线恢复尚未重做，仍应先停止并等待恢复确认，再退出服务。

## 运动世界与证据

读取页离开前台会取消定位订阅。目标应用观察与独立读取验收须分阶段进行；回到读取页后点击“开始读取”，再停止并核对恢复。运动世界由本人操作和检查，系统位置通过不能推出轨迹或记录有效。

“地图能定位”与“允许开始跑步”分开记录。当前正常对照已出现成功的网络位置回调，但开始跑步仍提示信号弱，尚未证明是轨迹引擎导致。读取器 1.1.0 可查看系统原生速度／方向、回调间隔及卫星／错误事件；卫星数量不能当作已获得 GNSS 定位。没有开启测试定位时，可临时拔线去室外采正常日志，回来接线导出；USB 轨迹会话仍须持续接线。

日志在忽略的 `local-data/sessions/`，包含原基线、精确坐标、目标标识、发送、独立读取、终点、清理和恢复事件。排错时保留原始记录，公开前脱敏。历次失败与版本限制见[USB 验收](verification/usb-acceptance.md)、[任务 5 报告](verification/task5-verified-executor.md)及[M0 结果](verification/m0-results.md)。
