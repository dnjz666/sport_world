# 操场轨迹定位模拟工具设计

日期：2026-10-16（Asia/Shanghai）

状态：用户已审阅并通过本设计规范，已授权编写实施计划。定位修改能力尚未在目标真机上验证。

## 1. 目标与交付范围

规划一个可控制手机定位沿操场移动的工具，让手机上的“运动世界”读取该定位。当前阶段交付设计与后续实施计划，真机试验作为开发的首个里程碑。

用户已确认的环境和优先级：

| 项目 | 要求 |
| --- | --- |
| 手机 | 华为 Mate 80 Pro |
| 系统 | HarmonyOS 7.0.0.109 |
| 目标应用 | 从华为应用市场安装并直接打开的“运动世界” |
| 首版运行方式 | 可以在运行期间持续通过 USB 连接电脑 |
| 优先升级方向 | 最好能在断开 USB 后继续运行 |
| 路线 | 首版围绕一条可配置的操场闭合路线完成闭环 |

安装来源不能代替对目标应用包名、版本和运行方式的核实，以上信息在真机阶段补充。

## 2. 需求与成功标准

| 编号 | 需求 | 判定依据 |
| --- | --- | --- |
| R1 | 针对上述目标手机验证可用的定位修改能力 | 记录设备、接口、调用身份、权限和实际结果 |
| R2 | 修改由系统提供给其他应用的定位 | 独立读取应用收到测试坐标及后续更新 |
| R3 | 沿操场路线按指定配速持续移动 | 发出与读取的坐标、时间、累计距离相互对应 |
| R4 | 支持圈数、方向、开始、暂停、继续、停止 | 控制状态与实际定位输出一致 |
| R5 | 首版允许持续 USB 运行 | 有线情况下完成整段路线与停止恢复测试 |
| R6 | 优先研究脱机能力 | 独立记录拔线、锁屏、后台运行和权限有效期结果 |
| R7 | 验证运动世界兼容性 | 分别记录定位读取、轨迹生成及记录有效性的结果 |
| R8 | 故障状态可诊断，停止结果可核实 | 日志保留错误和清理结果，不把请求成功等同于恢复成功 |

仅在本工具自己的界面绘制轨迹不满足 R2。目标应用读取定位、生成轨迹、认可运动记录是不同层次的结果，必须分别报告。GPS 定位试验也不能证明步频、身体传感器或其他运动条件已经满足。

R6 是高优先级升级项，不作为 USB 首版的完成条件；首版发布说明必须明确实际支持的运行方式。

## 3. 方案选择

| 方案 | 收益 | 约束 | 处理方式 |
| --- | --- | --- | --- |
| 电脑持续通过 USB 控制 | 便于查看连接、输出坐标和诊断结果 | 仍需真机定位入口，运行依赖电脑 | 首先验证并作为首版候选 |
| USB 启动后手机执行 | 用户可拔线使用 | 必须证明授权和执行能力在拔线后保留 | 首版验证通过后优先研究 |
| 完全独立的鸿蒙应用 | 操作最方便 | 需要手机应用自身取得接口、身份、签名和后台执行能力 | 根据真机证据决定是否演进 |

采用第一条路线并不预设权限更高。电脑端官方工具若确有真机定位注入能力，需验证其适用范围；手机应用若能调用定位模拟接口，也需独立验证其身份与授权。不能把 USB 连接能力当作定位修改能力。

## 4. 开发前的能力门槛

### G0：环境与接口证据

记录目标手机的实际系统构建、目标应用包名与版本、工具版本、设备连接结果，以及候选定位入口的官方依据。

对每个候选入口分别核实：

1. 适用的是 HarmonyOS 商用真机、OpenHarmony 开发设备，还是模拟器。
2. 调用主体是电脑调试工具、设备 shell、普通手机应用，还是系统应用。
3. 所需权限、应用身份和签名是否可实际取得，授权是否有有效期。
4. 是否修改系统定位，影响哪些定位读取路径。
5. 停止、断线、应用退出及设备重启后的真实行为。

查找手机设置中的模拟定位选项只是可选线索，不是 G0 的必经条件。

### G1：固定位置及独立读取

在同一目标真机上选用相距至少 100 米的两个测试点。通过候选入口依次设置位置，由另一个独立读取应用订阅系统定位，保存每个位置的坐标和时间。

比较前统一坐标系。独立读取坐标与测试坐标的水平差异应不大于 5 米，且应能观察到两个位置的先后更新。若接口明确存在舍入或其他限制，应先记录限制并调整判据，再运行试验，不能在失败后临时放宽判据。

调用返回成功、电脑界面移动、地图缓存变化均不足以单独通过 G1。

### G2：连续输出与恢复

通过一段短路线验证持续更新，记录速度、方向和时间推进。停止后通过独立读取确认恢复设备正常定位，检查是否仍残留测试位置。

### 分支决定

- G0、G1、G2 通过：进入 USB 最小版本。
- 只有手机端接口可用：电脑负责控制，手机辅助程序负责执行。
- 只有电脑端官方入口可用：电脑持续执行，拔线能力保持未证实状态。
- 接口或授权尚待外部处理：提交缺失证据清单，保留验证任务。
- 已证实没有可取得的真机修改路径：给出当前设备和约束下的不可行报告，停止完整产品开发。

## 5. 架构与模块边界

电脑端首版采用 TypeScript 本地服务与轻量本地界面。原生手机辅助程序仅在已验证的执行路径需要时引入，使用 ArkTS／ArkUI 和华为官方工具链。

| 模块 | 责任 | 输入与输出 | 依赖 |
| --- | --- | --- | --- |
| 本地控制界面 | 选择设备、配置路线与配速、控制会话、显示状态 | 用户操作转换为会话指令；展示结果 | 会话控制器 |
| 轨迹引擎 | 按经过时间计算沿线位置、速度、方向和累计距离 | 路线与运行参数转换为定位样本 | 独立时间源与距离计算 |
| 会话控制器 | 管理状态、暂停、停止、连接变化与清理 | 控制指令转换为执行和记录动作 | 轨迹引擎、定位适配层、日志 |
| HDC 连接层 | 识别目标设备、执行已确定的调试操作、报告连接状态 | 明确的设备与参数转换为调用结果 | 官方 HDC 工具 |
| 定位执行适配层 | 封装经 G0–G2 证实的定位设置与清理能力 | 定位样本转换为实际设备操作 | 已验证入口；必要时依赖手机辅助程序 |
| 验证与日志 | 区分预期输出、执行结果和独立读取结果 | 保存会话事件与证据 | 独立读取应用及本地文件 |

数据流：路线配置 → 轨迹引擎 → 会话控制器 → 已验证的定位适配层 → 系统定位 → 独立读取应用／运动世界。

轨迹计算与定位执行分离，使后续迁移到手机执行时可以保留路线与时间语义。TypeScript 与 ArkTS 的实现兼容性需在迁移时验证，不承诺直接共享全部代码。

本地服务绑定回环地址。HDC 调用使用明确的可执行文件、设备标识和参数数组，避免把界面输入拼接成任意 shell 命令。首版会话和路线保存在本地。

### 适配层能力报告

适配层在会话启动前报告：能否设置定位、执行主体位于电脑还是手机、能否验证停止清理、是否已经证明可以脱机。

只有经过对应试验的能力才能标为支持。未发现定位入口时界面显示能力尚未确认，不用演示数据冒充系统定位已修改。

## 6. 路线、时间与数据约定

### 路线配置

首版使用一条按顺序排列的经纬度点构成的操场闭合路线，可在本地编辑点位并预览形状。路线文件包含格式版本、坐标系、路线点和名称。

内部路线与发出样本统一为 WGS-84；若底图或导入来源使用其他坐标系，只在边界转换，并保存来源说明。对定位适配层的实际坐标约定还需通过 G0 核实。

运行配置包含配速（秒／公里）、圈数和方向。距离和预计时长从路线与运行配置计算，不设置相互冲突的独立目标。

### 轨迹推进

- 速度换算为 `1000 / 配速秒数` 米／秒。
- 先计算路线各段及累计长度，再按当前行进距离沿线插值。
- 按单调时间源计算已运行时长，避免定时器延迟逐次累加成距离误差。
- 暂停期间不累计行进时间；继续时不补跑暂停期间的距离。
- 暂停时保持最后一个坐标，按正常发送节奏刷新采样时间并将速度置为零；暂停本身不清理模拟定位，手动停止或完成全部圈数时清理。
- 跑完指定圈数后停止推进，并执行定位清理。
- 原型默认尝试每秒生成一个样本；实际发送频率以 G0–G2 验证的接口能力为准。

样本记录包含序号、经纬度、累计运行时间、采样时间、速度和方向。执行成功结果与独立读取结果分别保存。

输入校验覆盖坐标范围、有限数值、正配速、正整数圈数、有效路线长度和闭合连接。明显异常的跨段连接须提示用户修正。

## 7. 会话状态与故障处理

主要状态：未连接、已连接但能力未知、能力不可用、就绪、运行中、已暂停、已停止、需要恢复检查。

启动前检查目标设备、已验证能力和路线配置。运行期间出现接口拒绝、连接丢失或执行进程退出时，停止继续发送，并保留最后的执行结果。

### 停止与异常恢复

正常停止时按适配层支持的方式释放模拟定位，再通过独立读取确认恢复结果。清理失败时进入“需要恢复检查”，不能显示为已恢复。

对仅由电脑持续控制的路径，USB 断开后的手机行为必须实测；不能在设计中保证断线就会自动恢复真实定位。重新连接后先检查并清理残留状态，再允许开启新会话。

若手机辅助程序能够提供独立的停止和恢复能力，需在手机端提供可用的停止入口，并验证电脑退出时仍可操作。

日志记录设备与工具版本、状态变化、样本序号、预期和读取坐标、接口错误码及恢复结果。开发者账号密码、私钥和完整签名凭据不写入会话日志或源码。

## 8. 界面最小流程

1. 连接手机，选择目标设备，查看能力验证状态。
2. 配置一条操场路线、配速、圈数和方向，预览距离与预计时长。
3. 开始运行，显示状态、经过时间、累计距离、当前圈数和定位执行结果。
4. 暂停、继续或停止，查看清理及恢复结果。

“预期位置”“已提交位置”“独立应用读取位置”分别展示，便于辨认问题发生在轨迹计算、定位执行还是读取环节。

## 9. 开发里程碑与交付物

| 阶段 | 主要工作 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| M0 能力验证 | 完成 G0、G1、G2，确定执行主体与授权条件 | 设备和版本记录、真实调用步骤、日志、结论及恢复操作 | 证实存在可用的目标真机定位路径 |
| M1 USB 最小版本 | 实现路线、轨迹引擎、会话控制、适配层和本地界面 | 可运行 USB 版本、启动说明及已知限制 | 路线和控制测试、真机输出与恢复验证通过 |
| M2 运动世界兼容性 | 在指定版本中验证读取、轨迹与记录结果 | 分层兼容性报告和复现条件 | 实际达到的兼容层次有证据支持 |
| M3 脱机优化 | 验证启动后拔线或完全手机执行的可用路径 | 脱机版本或明确的不可行／待支持结论 | 满足相应脱机验收条件后才能标称支持 |

M0 没有可用路径时，M1–M3 不执行。M1 不以 M3 成功为前提；M3 失败时可保留已经验证的 USB 版本。

实施计划优先细化 M0。后续阶段按本设计的模块边界安排，但适配层的具体调用和签名配置必须绑定 M0 实际结果，避免编造尚未发现的定位注入命令。

## 10. 验证策略

| 验证项 | 方法 | 覆盖需求 |
| --- | --- | --- |
| 系统定位修改 | 两个固定点、独立读取及停止恢复 | R1、R2、R8 |
| 路线与时间计算 | 已知长度路线、跨弯道与圈界、暂停继续、延迟调度 | R3、R4 |
| USB 完整会话 | 真机完成指定路线，检查样本与状态 | R3、R4、R5 |
| 故障恢复 | 拔线、拒绝权限、定位服务不可用、进程退出、重新连接 | R5、R8 |
| 目标应用兼容性 | 指定版本中分别核对定位、轨迹、记录结果 | R7 |
| 脱机能力 | 拔线、锁屏、后台、手机端停止、权限或证书到期行为 | R6、R8 |

轨迹引擎用自动化测试覆盖距离、时间和暂停等计算规则；真机能力、目标应用兼容性和恢复行为保留实际设备证据，不用单元测试替代。

当前各项真机测试均未执行。本设计通过审阅只表示认可开发方向与验收要求，不表示目标设备能力已经验证通过。

## 11. 待 M0 决定的事项

以下事项有明确的验证任务，不预设结果：目标应用包名与版本；候选入口能否用于商用真机；权限及签名能否取得；定位执行主体；接口频率与坐标约定；断线及停止行为；目标应用兼容层次；脱机所需的后台执行条件与授权有效期。

这些结果应写入 M0 报告，并在启动 M1 前更新适配层实现安排；它们不影响先完成本次开发规划。
