# 鸿蒙手机定位与操场轨迹模拟：可行性调查

调查日期：2026-10-16（Asia/Shanghai）

状态：已进入本会话逐步执行，USB 调试连接、设备和应用身份已核实，定位写入能力仍未验证。本文保留规划阶段的公开资料调查；最新实际结果见[写入入口审计](../verification/location-write-entry-audit.md)。正式设计见[操场轨迹定位模拟工具设计](../superpowers/specs/2026-10-16-harmonyos-track-location-design.md)，后续步骤见[实施计划](../superpowers/plans/2026-10-16-harmonyos-track-location-plan.md)。

## 1. 目标和用户约束

目标是在手机上运行一个软件，让手机输出沿操场移动的定位，并由另一款应用“运动世界”读取这些定位。

用户已确认：

- 手机：华为 Mate 80 Pro。
- 系统：HarmonyOS 7.0.0.109。
- 运动世界从华为应用市场安装，直接打开。
- 第一版可以在运行期间持续通过 USB 连接电脑；优先争取后续断开连接也能运行。

后续补充：用户报告手机设置只看到“位置”相关选项，尚未找到明确的模拟定位入口，并询问采用电脑 USB 连接后是否仍需验证系统能力。用户随后明确接受持续 USB 连接，同时偏好能够断开连接；这取代了早期必须手机独立运行的硬约束。

原始请求的交付物是开发规划，现已获准逐步执行。下文中的前期调查结论应结合最新 M0 证据阅读，不将资料存在视为真机功能已实现。

规划时仅依据安装方式选择调查方向；执行时已通过前台记录与系统包管理器确认鸿蒙包 `com.zjwh.hm_wh_physicalfitness`，版本 7.3.92。

成功需要分别证明：手机能够输出模拟定位；独立应用能够读到该定位；运动世界能够读取该定位。若还要求生成有效运动记录，需要另行验证其完整判定条件。仅在我们自己的界面画出跑步轨迹，不满足原目标。

## 2. 已核实的公开资料

### 2.1 定位模拟是系统接口

OpenHarmony 官方接口文档将 `enableLocationMock` 和 `setMockedLocations` 标为系统接口，要求 `ohos.permission.MOCK_LOCATION`，并分别列出缺少权限（201）和非系统应用调用系统接口（202）的错误。

这意味着“获得定位读取权限”不能作为“可以修改系统定位”的证据；接口身份检查和权限检查都需要核实。

来源：[OpenHarmony 定位服务系统接口](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-location-kit/js-apis-geoLocationManager-sys.md#geolocationmanagerenablelocationmock)。

### 2.2 模拟定位权限有应用等级和授权条件

OpenHarmony 官方权限表把 `ohos.permission.MOCK_LOCATION` 标为 `system_basic`、`system_grant`，同时标注支持证书授权。

因此不能把它当作用户点击普通权限弹窗即可取得的权限；也不能只凭“系统权限”四个字就断言所有证书申请路径都不可行。需要查明华为商用系统对目标开发者、应用身份和签名证书的实际准入条件。

来源：[OpenHarmony 系统应用权限表](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/security/AccessToken/permissions-for-system-apps.md#ohospermissionmock_location)。

华为商用开发平台也提供部分 ACL 权限申请与自动签名流程。其官方文档区分临时调试 Profile 和审批后的正式 Profile，并要求符合相应权限的使用场景。但这不是 `MOCK_LOCATION` 已向该项目开放、或系统接口身份检查已满足的证明。必须检查具体权限清单和准入结果。

进一步核对：该文档列出的 DevEco Studio 5.0.0、6.0.0 Beta3、6.0.1 Release 与 6.0.2 Beta1 的历史支持项中未列出 `MOCK_LOCATION`；文档说明从 DevEco Studio 6.1.0 Beta2 起须参考另一份“受限开放权限”清单。尚未取得新版清单中该权限开放的正面证据，因此不能把历史列表缺项推断为当前系统绝对不支持，也不能把通用 ACL 流程当作该权限可申请的证明。这里的 DevEco Studio 版本与手机 HarmonyOS 版本不是同一个版本号。

来源：[华为自动签名](https://developer.huawei.com/consumer/cn/doc/doccenter-deveco-studio/ide-signing-auto)。

### 2.3 Android 资料不能直接证明目标手机可行

Android 官方存在测试定位 Provider 接口；华为旧版 HMS Toolkit 定位示例也明确是 Android 工程。这些文档不能作为 HarmonyOS 7 原生应用可修改系统定位的证明。

来源：[Android LocationManager](https://developer.android.com/reference/android/location/LocationManager)、[华为 HMS Toolkit 定位示例](https://developer.huawei.com/consumer/cn/codelab/HMSLocationKit-Toolkit/index.html)。

### 2.4 模拟器能力不能代替真机结论

华为 DevEco Studio 官方介绍明确提供模拟器 GPS 场景模拟能力。这支持开发测试用途，不能证明同样的定位修改能力向 Mate 80 Pro 上的普通应用开放。

来源：[华为 DevEco Studio](https://developer.huawei.com.cn/consumer/cn/deveco-studio/)。

### 2.5 USB 连接是调试通道，不是定位修改能力的证明

HDC 官方文档提供设备枚举、命令执行、应用安装和日志等调试能力。连接成功仅能证明调试通道可用，不能单凭此结果推定模拟定位接口可调用、所需权限已取得，或运动世界可读取修改后的定位。

来源：[OpenHarmony HDC 文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/dfx/hdc.md)。

## 4. 下一步要取得的证据

### A. 手机设置线索

用户已报告仅看到“位置”相关选项。允许访问位置不构成允许修改系统位置的证据。

查找“模拟位置”“模拟定位”选项仅是可选调查线索，不是继续研究的必经条件。选项存在不能单独判定方案可行；没有找到选项也不能单独证明不存在其他官方开发入口。如果采用电脑辅助验证，可以直接通过 HDC 和官方开发文档检查实际设备与可用接口，不再等待找到设置选项。

### B. 商用系统准入条件

核对目标系统适用的华为官方接口、应用身份要求、签名和证书授权流程。必须有普通开发者可实际取得的支持路径，才值得安排定位写入原型。

USB 连接不能替代该项验证。如果依赖电脑端的官方调试注入入口，则需另外核实该入口是否支持目标商用真机，以及它与手机应用接口的权限条件有何区别。

### C. 最小真机验证

如果 B 确认存在可用路径，先安排最小原型，不先开发完整界面：

1. 一个应用输出固定测试坐标。
2. 另一个独立应用通过系统定位接口读取坐标，避免把内部预览误认为系统定位已改变。
3. 输出连续移动坐标，检查时间推进、位置更新和停止恢复。
4. 先验证持续 USB 连接下的运行和停止行为；断开电脑后继续运行作为后续优化目标，另行验证拔线、锁屏、后台运行、权限有效期和恢复定位。
5. 在前述结果成立后，再验证目标版本运动世界的定位读取。

开发、签名、打包是否使用电脑，与最终运行是否依赖电脑是两个不同的问题。最新约束允许首版持续使用电脑，脱机能力是优先优化项。

采用 USB 辅助时，建议验证顺序为：HDC 能识别目标手机 → 确认适用接口和权限 → 固定位置写入及独立读取 → 连续轨迹与停止恢复 → 运动世界兼容性 → 脱机运行优化。不能把“手机连上电脑”当作后续各项均已通过。

USB 用途已明确：允许运行期间持续连接，最好能够断开。设计优先让定位执行方式与轨迹生成分离，便于在官方能力得到验证后选择电脑持续控制、电脑启动后手机执行，或完全手机端执行；三种形态都不能预设目标真机已具备定位修改入口。

## 5. 后续开发的条件和边界

如果真机验证通过，再讨论原生应用的路线设置、按时间推进的轨迹计算、定位适配、开始/暂停/停止控制，以及故障恢复。

如果只证明了自己应用内的轨迹预览，原目标仍未实现。如果没有可取得的真机系统定位修改能力，在当前设备与运行约束下应停止完整产品开发，而不是把预览功能包装成已经能影响运动世界。

当前结论：原目标的关键前提尚未证实；规划可按“能力验证 → USB 最小版本 → 目标应用兼容性 → 脱机优化”展开，并将真机定位接口与授权验证列为开始完整产品开发的条件。现有资料不构成 USB 版或脱机版必然可用的承诺。
