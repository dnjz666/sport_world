日期：2026-10-18。任务 5 已按用户要求快进合并到 main（af185bb），合并后原有 60 项测试通过。随后在当前目录创建 codex/task6-session-recovery，实现本任务，未创建工作树、操作手机或修改真机证据。

## 实现结果

[SessionController](../../desktop/src/core/session.ts) 使用计划约定的构造参数、指令和快照接口，连接真实 Replay、执行器、独立读取器、HDC 与日志。配置和快照均复制；预期样本、提交回执、独立读取分别保存。同一代次的 tick 合并，保持采样间隔；stop 立即使旧准备／发送／读取结果失效，先进入 stopping，再按实际清理和观测决定状态。

启动先核对显式 USB 目标、有效能力及当前系统，主动关闭残留模拟，再用设备时钟建立边界，在 35 秒内取得 5 个不同的新稳定回调：精度不超过 50 米、距中位点均不超过 10 米且未明确标记模拟。取得原基线后才 prepare；超时返回的第五个样本也不能启用模拟。USB 模式及原有能力约束未扩大。

停止关闭被接受后保持 recovery_required。恢复采用原有 M0／任务 5 判据，在 45 秒内取得至少 3 个不同的独立回调，并同时满足：

| 条件 | 判据 |
| --- | --- |
| 清理 | 工具关闭及本次资源清理被接受 |
| 新鲜度 | 位置／接收时间均晚于本次清理边界；用设备时钟核对，接收距设备当前时间不超过 5 秒，位置与接收时间差绝对值不超过 5 秒 |
| 位置质量 | 精度可读且不超过 50 米，isMock 不为 true；不可读的来源／模拟标记保留 null |
| 原会话基线 | 距本次启动前正常基线不超过 50 米，不能中途换基线 |
| 排除测试位置 | 距本会话所有尝试注入坐标均至少 100 米 |
| 等待期限 | 观测返回后再次检查 45 秒截止，迟到样本不能将状态改为 stopped |

断线会使旧关闭结果和恢复样本失效；重连须重新 stop。清理失败、缓存／重复／错误位置、缺失精度、明确模拟、超时都不能确认恢复。显式重试 stop 沿用原基线，重新清理并建立时间窗口。恢复未确认时拒绝新配置与启动；真实基线与模拟路线过近也会保守地无法通过。

[JSONL 日志](../../desktop/src/logging/journal.ts) 串行追加并在入队时复制输入，记录 expected、sent、observed、cleanup、recovery_started、recovery 及故障。恢复起始事件保留设备时间边界、固定判据、原基线和尝试注入坐标；超时只记一次失败结果。敏感键、错误文本中的常见凭据别名及 PEM 私钥被过滤。写入错误对调用方可见，控制器仍尝试清理，但日志故障后不能宣称恢复成功或重新启动，修复后须重新建立控制器。实际日志含精确位置及目标标识，只保存至忽略的 local-data。

为适配计划中固定注入的执行器实例，任务 6 调整了其生命周期：新实例经证据／系统核对后可主动 stop；每次 stop 重新派发关闭；成功清理后才可再次 prepare，并使用新随机目录及从头递增的序号。GPX 传输、目标选择、最后派发前授权检查、摘要清理及已有会话过期后可停止的规则保持原有实现。任务 5 的设备证据与源码摘要保留为当时实测版本，不以本次逻辑测试声称新版本已经真机复验。
